# v0.6 QSearch SEE Pruning — initial controlled strength screen

**Date:** 2026-11-02. **Decision:** keep the feature independently switchable but **disabled by default**. Neither 200-game experiment establishes that it is stronger; keep v0.5 as the strongest validated release, and do not merge v0.6 based on these results.

## Experimental setup

- [Successful two-match workflow 41375400592](https://github.com/LorFerSilve/Bitboard-Chess-Engine/actions/runs/41375400592), exact PGNs/Fastchess logs/metadata included in its `v06-qsearch-see-tests` artifact.
- Code revision: `7a70e442ec803cfced78836c21b5706ab779695b`, before changing the QSearch default. The default change does **not** change the explicit candidate/baseline configurations below.
- Portable Linux Release/LTO, `benchmarks/openings/extended.epd` (95 positions), `3+0.03` seconds, hash 16 MiB, two concurrent games, 100 color-reversed opening pairs (200 games) per experiment.
- Candidate in both tests: `All Heuristics=false` followed by `QSearch SEE Pruning=true`, no other new v0.6 heuristics enabled.

The first estimate is suggestive but crosses zero; the second does not indicate a strength advantage over the historical release. The pair of estimates is **not** a direct measurement of the all-off v0.6 control versus historical v0.5 because seeds differ. Do not subtract these Elo figures or combine their statistical margins as if they were measured in one matched experiment. The 95-position corpus is reused across experiments, and multiple earlier v0.6 screens increase selection bias.

## Engineering decision

- Retain `QSearch SEE Pruning` as an explicitly controllable UCI experiment, **off by default**. `setoption name QSearch SEE Pruning value true` enables it, while `setoption name All Heuristics value false` followed by the per-feature enable isolates it.
- Preserve tactical exceptions: it never prunes an evasion when already in check, a checking capture, or a promotion. No claim of complete tactical correctness/strength follows solely from the regression tests.
- Existing initial regression tests and Linux/Windows/optional Syzygy builds passed at commit `006d6d19f4d05a1f8c90208f11d66612d7500184`.
- For release consideration, a fresh independent opening **corpus** and adequate game count/time controls are needed. Do not merge the all-on v0.6 candidate; historical v0.5 remains the strongest validated release.
